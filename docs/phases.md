# Фазы реализации и результаты тестов

Тесты: `pytest -q` (SQLite) и `BOT_TEST_PG_URL=… pytest -q` (те же + PostgreSQL 16). Сеть не нужна: crawler и AI
подменяются `testing/fake_crawler.py` (семантика фильтров, курсоров и ленты crawler) и `testing/fake_ai.py`
(намеренно «выдумывает», чтобы проверить защиту). Итог: **64 теста на SQLite, 95 с PostgreSQL — все зелёные**, `ruff check` чистый.

## Фаза 0 — контракт и клиент
* Найдено: в репозитории Telegram-бота ещё нет (crawler называет его «planned»), папка проекта была пустой → бот создан
  как новый сервис. Существующий код — только crawler; он не изменён.
* Прочитан живой OpenAPI, выделены 9 маршрутов `/api/bot/v1` и 21 схема → `contracts/`, модели сгенерированы.
* Выяснено: auth не описан в OpenAPI (Bearer по коду), Bot API на сервере выключен (503).
* Клиент: ретраи, 429/Retry-After, 401/422/503, 400/409 для ленты, keyset-пагинация.
* Тесты: `test_contract.py` (12 с параметризацией), `test_client.py` (7).

## Фаза 1 — анкета, поиск, объяснимый рейтинг
* 33 шага как данные, движок без Telegram, черновик в БД (переживает рестарт), «Назад/Пропустить/Готово/Любой/Изменить»,
  поиск по справочникам, свободный ввод, редактирование из карточки профиля (спрашиваются только новые применимые шаги).
* Модель критериев в словаре crawler; план запросов; hard-фильтры; оценка с причинами.
* Тесты: `test_matching.py` (9), `test_questionnaire.py` (5), `test_search.py` (4).

## Фаза 2 — подписки и надёжные уведомления
* Сессии поиска («Ещё», «Подписаться»), подписки, inbox/курсор, обработчик с водяными знаками, outbox, отправитель,
  тихие часы, лимит, сводки, пауза/удаление, MANUAL-режим, обновления по опции, ресинхронизация после 409.
* aiogram-слой: все команды, карточки, «Почему N?», сохранённые, обратная связь, приватность, удаление.
* Alembic `0001`; проверено `upgrade/downgrade/upgrade` на PostgreSQL и SQLite, `alembic check` без расхождений.
* Тесты: `test_feed.py` (12: пробелы между предпросмотром и подпиской, падения, дубли, 409, блокировка, лимиты…),
  `test_bot_e2e.py` (4 сценария, плюс 1 AI-сценарий в фазе 3, через настоящий Dispatcher с фейковой сессией Telegram).

## Фаза 3 — AI
* Шлюз провайдера (бюджет, лимиты, журнал), парсер профиля (правила + LLM, проверка цитат), подтверждение фактов,
  CV (DOCX/PDF, очистка ПДн, шифрование, удаление), ассистент поиска текстом, семантический реранкер с кэшем,
  объяснения с проверкой ссылок, обратная связь → мягкие веса.
* Тесты: `test_ai.py` (10) и e2e-сценарий с согласием, подтверждением фактов и кэшем пояснения.
* Демо расхода (`vacancies-bot demo --with-ai`, 20 подписок, 60 событий): **0 LLM-вызовов на сопоставление**,
  5 вызовов на 10 нажатий «Почему?» (повторы из кэша), 5 запросов эмбеддингов на 13 текстов, 20 сообщений Telegram на
  200 совпадений (сводки).
