# Допущения, ограничения, открытые вопросы

## Допущения
1. **Существующего Telegram-бота нет.** Папка проекта была пустой, в crawler бот описан как «planned» → создан новый сервис
   `vacancies-bot`; «не дублировать функциональность» соблюдено: поиск, фильтры, геокодирование, извлечение навыков и
   языков остаются в crawler, бот их только использует.
2. **Аутентификация** — Bearer из `gcc_core/botauth.py` (в OpenAPI не объявлена).
3. Отдельная БД PostgreSQL (вместо схемы `bot` в БД crawler) — проще изоляция и удаление данных.
4. «Сфера» (вопрос 20) = группы специализаций crawler; crawler не фильтрует по отрасли работодателя → только ранжирование.
5. Уровень позиции (вопрос 05) — мягкий сигнал: crawler определяет его по названию.
6. Исключения (вопрос 25) — по названию вакансии и компании (не по описанию), локально.
7. Свободные «обязательные условия» (вопрос 23) не проверяются автоматически: показываются в карточке как «Проверить».
8. Неподтверждённые факты из текста/CV **не сохраняются**: после подтверждения они получают `user_confirmed`. Поле
   `source` в модели поддерживает `*_unconfirmed` для будущего режима «сохранить черновик».
9. Неоднозначная отправка в Telegram (обрыв сети после запроса) не повторяется — выбрана защита от дублей.
10. Оплата/квоты AI считаются по ценам из `.env` (`AI_PRICE_*`); для локальной модели — 0.

## Ограничения текущей версии (P2)
* Тексты интерфейса: RU и EN полностью; UK и DE — только старт/навигация, остальное на EN.
* Админ-панель и метрики — только `ai_usage`, `notification_outbox`, логи; дашборд не делался.
* PDF-сканы без текстового слоя не распознаются (OCR не подключён) — бот просит DOCX/текстовый PDF.
* «Подсказка расширить поиск» показывается при пустом результате поиска; периодическая подсказка для подписок без совпадений не реализована.
* Карьерные рекомендации (P2, п. 13) не реализованы.
* Webhook-режим не настроен (polling); для webhook достаточно заменить запуск в `main.py`.

## Проверено против живого сервера
* `openapi.json` прочитан с `https://crawdler.duckdns.org` 2026-11-10, совпадает с `docs/openapi.json` репозитория.
* Сами запросы к Bot API проверить нельзя, пока на сервере не задан `BOT_API_KEYS` (503). После настройки —
  `vacancies-bot check-crawler` проверит все 8 вызовов и валидирует ответы по схемам.
