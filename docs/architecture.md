# Архитектура

```text
Crawler (FastAPI, не меняется) ── GET /api/bot/v1/{facets/*, jobs[/id], changes[/head]}  (Bearer, read-only)
        │
        ▼
CrawlerClient (сгенерированные модели, ретраи, 429/409/400)
        │
 ┌──────┼──────────────────────────┬──────────────────────────────┐
 ▼      ▼                          ▼                              ▼
Facets  SearchService            FeedIngestor ──► crawler_event_inbox ──► FeedProcessor ──► notification_outbox ──► Sender ──► Telegram
(кэш)   query plan → hard filter  (атомарно с курсором)          (водяные знаки подписок)     (тихие часы, лимит, сводки)
 │      → оценка → [rerank AI]
 ▼      ▼
Questionnaire Engine (FSM, черновик в БД) ◄── aiogram handlers ──► AI: parser / assistant / CV / explain (по согласию)
        │
        ▼
PostgreSQL (своя БД бота): bot_users, candidate_profiles, questionnaire_drafts, subscriptions, subscription_matches,
saved_jobs, feedback, crawler_event_inbox, crawler_sync_cursor, job_cache, notification_outbox, search_sessions,
cv_documents, ai_usage, embedding_cache, facet_cache
```

Один процесс: polling aiogram + 4 цикла (лента 60 с, обработка 15 с, отправка 5 с, обслуживание 1 ч). На PostgreSQL
воркеры защищены advisory-lock: второй экземпляр бота не обработает ленту повторно.

## Поиск и оценка
1. `query_builder.build_queries` — до 6 запросов: (локация | регионы | города | remote из страны) × (специализации |
   свободная роль `q` | основные навыки | группы для BROAD). Параметры — только из контракта.
2. Результаты объединяются по `id`, к каждой вакансии применяется `matching.hard_filter` (то же, что для ленты):
   закрыта, исключения (название/компания), локация или право удалёнки из страны проживания, формат, занятость,
   язык (NO → отсев, WARN → предупреждение), строгая зарплата, специализация по ширине поиска.
   **Неизвестное значение ≠ несоответствие**: идёт в `unknowns` и снижает полноту данных.
3. `matching.score_job` — веса 25/25/15/15/10/10 (роль, навыки, опыт/уровень, гео/формат, языки, прочее), множители от
   обратной связи (0.5–2.0, только мягкие компоненты), опционально семантика (`AI_SEMANTIC_WEIGHT`, только для прошедших
   hard-фильтр). Каждое слагаемое оставляет причину: `why` / `gaps` / `unknowns` / `checks` + `completeness`.

## Надёжность ленты (гарантии)
| Ситуация | Поведение |
|---|---|
| падение между чтением страницы и сохранением | курсор и события в одной транзакции → страница перечитывается, `ON CONFLICT (event_id) DO NOTHING` |
| события между предпросмотром и «Подписаться» | baseline (последний event_id после догоняющего опроса) фиксируется **до** поиска; подписка начинает с него |
| начальная выдача | сохраняется как `subscription_matches(origin=initial)` → никогда не уходит как «новая» |
| повторная обработка / падение обработчика | совпадения `UNIQUE(subscription_id, job_id)`, outbox `UNIQUE(dedup_key)`, водяной знак подписки двигается в той же транзакции |
| одна вакансия в нескольких подписках | один outbox-ключ `new:<user>:<job>`, список подписок в сообщении |
| crawler недоступен при получении деталей | событие ждёт (backoff), глобальный водяной знак не двигается, порядок сохраняется; после `EVENT_MAX_ATTEMPTS` — `skipped` + лог |
| 409 / 400 курсора | курсор из `/changes/head`, `resync_since`, поиск `/jobs?new_since` по подпискам |
| Telegram 429 / 5xx | повтор позже; 403 (бот заблокирован) → подписки выключаются |
| падение во время отправки | строка «sending» с арендой → после истечения `unknown`, **не повторяется** (лучше потерять одно сообщение, чем слать дубли после каждого рестарта) |
| `job.updated` | пересчёт существующих совпадений; сообщение только при `notify_updates` и значимых полях |
| `job.closed` | отмена ожидающих уведомлений, отметка в «Сохранённых», без рассылки |
| пауза подписки | при возобновлении водяной знак = текущий: архив паузы не присылается |

## Уведомления
`planner.due_at`: IMMEDIATE (с учётом тихих часов), MORNING/EVENING (в часовом поясе пользователя), MANUAL (без push,
список по кнопке). `Sender`: дневной лимит считается по сообщениям (сводка = 1); ≥ `DIGEST_THRESHOLD` элементов или
сводочный режим → одно сообщение со списком; превышение лимита → перенос на утро сводкой.

## AI-конвейер (экономный)
правила/валидация → детерминированный отбор → (опц.) эмбеддинги только для топ-30 прошедших фильтры → (опц.) LLM-пояснение
**по кнопке** «Почему N?» и с кэшем. Сопоставление ленты с подписками LLM не использует вовсе.
Эмбеддинги вакансий кэшируются по хешу содержимого (одна вакансия — один вызов на всех пользователей), профиля — по хешу текста.
`AIGateway`: месячный бюджет, лимит вызовов на пользователя в сутки, журнал `ai_usage` (токены, стоимость, ошибки — без текстов).
Любая ошибка → `AIUnavailable` → правила. Провайдер — любой OpenAI-совместимый endpoint (Ollama/vLLM/LiteLLM/облако).

Защита от выдумок: каждый факт из текста/CV обязан содержать дословную цитату (`evidence`), уровень CEFR и число лет —
только если они есть в цитате; навыки сводятся к каноническим именам crawler, роли — к таксономии или помечаются как
свободный текст. В объяснении каждый пункт ссылается на номера фактов; пункты без ссылок или с числами, которых нет в
цитируемых фактах, отбрасываются. Тексты вакансий и CV — данные, не инструкции.

## Приватность
* Не спрашиваются пол, возраст, происхождение, религия, семейное положение, фото, адрес, гражданство.
* Согласие на AI (версионируется) и отдельное согласие на CV; отзыв в `/privacy`.
* CV: файл только в памяти; сохраняются SHA-256/тип/размер; текст очищается от e-mail, телефонов, ссылок, дат,
  адресов, строк с датой рождения/гражданством/семейным положением **до** отправки в модель; хранится зашифрованным
  (Fernet) до подтверждения фактов или максимум `CV_RETENTION_HOURS`, без ключа — не хранится вовсе.
* `/delete_me` — реальное удаление (каскад по всем таблицам), в `ai_usage` остаются анонимные строки стоимости.
* Логи: без текстов пользователей, токенов, CV; httpx-логи (URL с поисковыми словами) приглушены.
